# Pin Carbon Copy（PinCC）设计说明

正式全称 **Pin Carbon Copy**；本文与代码里的 **PinCC** 是同一产品的简写（命令、程序集、路径不变）。本文记录其结构、关键机制和取舍。开发过程：先写草案；再做调研，覆盖微软便笺、Microsoft To Do、约 20 个同类开源/商业应用、WPF/Win32 的 DPI 与分层窗口细节、各 CLI LLM 的非交互调用方式；然后从需求覆盖、技术正确性、KISS/DRY、竞品借鉴四个角度批评草案；最后合并成本版（v2）。

原则：**KISS**，能交给系统或现有程序的都不自己做；**最小正交**，一次手势只改一个概念；**DRY**，所有修改只从一个入口进出。

## 1. 结构

```text
Program.Main ── 带参数 ─► Core.Cli（纯文本接口；不加载任何 WPF 类型）
      └──────── 不带参数 ─► UI.App ─► Desk（唯一修改入口 + 布局 + 1 秒节拍）
                                 ├─ CardWindow ×N   每张卡片一个分层顶层窗口
                                 ├─ HubWindow  ×显示器数   “+” 与速拨
                                 ├─ ManageWindow           卡片库 + 设置
                                 └─ MessageWindow          隐藏顶层窗口：热键、显示器变化、时间变化、电源恢复
Core：Db(winsqlite3) · Store(列级差量写 + rev + 操作组) · Card(派生状态) · When · Markdown · Fetch · Llm · Agents(执行器) · Skills(技能管线) · Proc(Job)
```

CLI 和 GUI 共用 `Store`，是同一个库的两个进程（WAL，busy_timeout）。GUI 每秒读一次 `PRAGMA data_version`；这个值只在**别的**连接提交后才会变化，一旦变化就全量重读（通常只有几十行）并比对差异。

## 2. 数据

```text
cards(id, rev, body, images(JSON), summary, meta(JSON), color NULL=自动, topmost, opacity, collapsed,
      free, mon, x, y(相对显示器工作区的 DIP 偏移), w, h NULL=自适应, remind_at, done_at, deleted_at, created_at, updated_at,
      ord NULL=按创建时间)       -- ord：拖动排序后的位置
ops(id AUTOINCREMENT, grp, at, card_id, op, before, cols)
                                           -- before = 该卡片在这一组操作之前的完整 JSON；cols = 这组操作改过的列
settings(key, value)                       -- PRAGMA user_version = 2（2 加了 ord）；遇到更高版本的库只读，拒绝写入
```

- **只存用户的决定，其余都是派生值**：
  - 类型和来源：正文第一行是 http(s) 网址就是链接卡片，是绝对路径就是文档卡片，只有图片没有正文就是图片卡片
  - `Note`：正文去掉来源那一行
  - 任务进度：只统计正文里的任务
  - 是否到期
  - 摘要是否过时：`meta.SumHash ≠ InputHash`
  - 自动颜色：配色模式 × 卡片 id、类型或标签
- **写入**：`Store.Mutate(group, id, change)` 在 `BEGIN IMMEDIATE` 中重读当前行，应用修改，**只写有变化的列**，并执行 `rev = rev + 1`，条件是 `WHERE rev = ?`。GUI 和 CLI 同时修改同一张卡片的不同字段时，谁的修改都不会被覆盖。`--if-rev` 让 CLI 检测到冲突时拒绝写入，退出码为 3。
- **操作组**：一次手势就是一组，例如一次编辑会话、一次拖动、一次“全部平铺”或一条 CLI 命令。同一组里，每张卡片记录一次它在这组之前的状态，以及这组改过的列（多次写入取并集）；如果别的进程在这组两次写入之间改过这张卡片，再记一条，保证对方的版本也留在历史里。`Restore(grp)` 按倒序**只写回这些列**，撤销“新建”就是删除；恢复本身也是新的一组，所以可以再撤销。组号取第一条记录的 id（AUTOINCREMENT，清理后也不会复用）。
- **派生数据不进历史**：网页标题、描述、文件信息这类元数据用 `journal: false` 写入；自动生成的摘要记入历史，但不进 Ctrl+Z 栈，只有用户点 ✨ 生成的摘要才能用 Ctrl+Z 撤销。
- 布局计算出的位置**从不写库**。位置只在用户拖动或调整大小结束（`WM_EXITSIZEMOVE`）时保存。拔掉显示器等情况下把卡片拉回屏幕内，只影响显示，显示器接回后卡片会回到原位。
- **保留与清理**：
  - 已删除的卡片和操作记录按保留期（默认 30 天）清理；已完成的卡片永久保留，作为归档
  - 图片只有在没有任何卡片或操作记录引用它时才删除
  - 每天用 `VACUUM INTO` 备份一次，保留 7 份

## 3. 窗口与 DPI

- 清单文件声明 PerMonitorV2。所有放置都用 `SetWindowPos`、以**物理像素**计算，不使用 `Left`/`Top`，也不读 `SystemParameters`。
- **跨不同 DPI 的显示器**：先把窗口中心移到目标显示器上，让 `WM_DPICHANGED` 在目标 DPI 下处理；再设置精确矩形；如果 DPI 仍不对，重试一次。同一 DPI 下的多次移动用一次 `DeferWindowPos` 批量完成。
- WPF 处理 `WM_DPICHANGED` 时调用的 `SetWindowPos` 不带 `SWP_NOACTIVATE`（dotnet/wpf#7561）。PinCC 的钩子在 WPF 之前运行，给这一次调用补上这个标志。
- **卡片窗口**：
  - 样式：`WindowStyle=None`、`AllowsTransparency`、`ResizeMode=NoResize`，另加 `WS_EX_TOOLWINDOW`，不出现在 Alt+Tab 中
  - 吞掉 `SC_MAXIMIZE`/`SC_MINIMIZE`
  - 调整大小：`WM_NCHITTEST` 把卡片内侧 6 DIP（角上 12 DIP）当作边框
  - 图片卡片在 `WM_SIZING` 中锁定宽高比
- **+ 按钮和提示条**：`WS_EX_NOACTIVATE`，点击时不抢焦点。+ 按钮手动实现拖动，因为不激活的窗口用 `DragMove` 看不到实时反馈；松开时吸附到最近的屏幕角。
- **提醒和颜色面板**：用带 Owner 的真窗口，不用 WPF Popup，因为 Popup 拿不到输入法焦点。卡片收到 `WM_ACTIVATE(WA_INACTIVE)` 时检查新激活的窗口是否由自己拥有，是的话就不退出编辑。
- **全屏检测**（每秒一次）：前台窗口铺满了它所在的显示器（不算最大化窗口和带标题栏的窗口），或者系统报告处于演示/D3D 全屏模式时，该显示器上的 + 隐藏、卡片暂时取消置顶并退到全屏窗口之后；只有当所有到期卡片都在全屏的显示器上时，提醒声才推迟到退出全屏后再响。+ 按钮隐藏时仍占着布局位置，进出全屏不会引起重排。

## 4. 卡片交互

| 对象 | 手势 | 结果 |
|---|---|---|
| 文字 | 双击 | 进入编辑，光标落在点击的源码行（纯文本块可以精确到列） |
| 来源标题、链接 | 单击 | 用默认程序打开（可执行文件只在资源管理器中定位） |
| 任务方框 | 单击 | 勾选，只改写这一行源码 |
| ☑ 进度 | 单击 | 快速加一项（见下） |
| “已完成 N 项” | 单击 | 展开 / 收起折叠的已勾选项（只影响显示，不写库） |
| 图片 | 双击 / 悬停 × | 用系统查看器打开 / 移除（可撤销） |
| 胶囊 | 单击 | 展开；如果是因为空间不足才变成胶囊，就临时展开 |
| 其他区域 | 拖动（超过系统拖动阈值后） | 平铺的卡片：拖到队列里就插入最近的位置，其他卡片让位；拖离队列、自由卡片：移动卡片，之后卡片记住自己的位置 |
| 内容 | 滚轮 | 上下滚动放不下的内容（没有滚动条，还有内容的一侧淡出） |

- **只有两个状态**：查看和编辑。
  - 进入编辑：双击文字、按 Enter，或新建卡片。
  - 退出编辑：卡片失去焦点，或按 Esc，两者都会保存。
  - 编辑时隐藏整行操作按钮，所以 ○ 永远只表示“完成这件事”，不会被误当成“编辑完成”。
- **新卡片在有内容之前不入库**。什么都没写就离开，不留任何记录。清空已有卡片等于删除，同一次撤销可以把内容找回来。
- **完成或删除**：卡片原地收成“已完成 · 撤销”，原来整张卡片的位置在布局里继续保留；鼠标离开 4 秒后关闭，然后才重新平铺。这样不会有别的卡片滑到撤销条下面。在撤销条上按 Ctrl+Z 等同于点“撤销”。
- **临时展开**：点击因空间不足而变成胶囊（或被隐藏）的卡片，它在原处完整显示，鼠标离开后恢复；这期间不写库。
- **临时查看**：滚动位置和拉宽（没有置顶的卡片拉得比保存的宽度更宽）都不写库，卡片置顶或激活时保持，否则回到开头、恢复保存的宽度（`CardWindow.Settle`，在鼠标离开和失去激活时检查）。拉宽期间卡片原地不动，按障碍物处理。置顶的卡片拉宽照常写库。
- **放不下的清单**：按保存的宽度排版后放不下时，改为每项一行、末尾省略（判断依据是折行时的高度，所以不会来回切换）。
- **只有一张图片的新卡片**：在空白的新卡片里粘贴图片，直接结束编辑，变成按 1:1 像素显示的悬浮图片。WPF 的 TextBox 只接受文字粘贴，剪贴板里只有图片或文件时 Ctrl+V 会被静默忽略，所以编辑框自己处理这种 Ctrl+V / Shift+Insert。
- **点 + 贴剪贴板里的图片**：剪贴板里是 PinCC 上次使用之后新复制的图片（位图且没有文字，或者全是图片文件）时，点 + 直接生成 1:1 图片卡片。“上次使用”按 `GetClipboardSequenceNumber` 记：PinCC 读过或写过剪贴板（包括卡片上的 Ctrl+C）就记下当时的序号，所以同一次复制只贴一次，再点 + 就是空白卡片。Office 复制单元格、浏览器复制选区时会同时带上文字和位图，这种情况按文字处理，不贴图。
- **快速加一项**（清单卡片）：底行变成一个单行输入框。回车加入一项 `- [ ] …`，位置在最后一个任务及其子项之后，缩进和列表符号跟随清单的最外层，然后可以接着输入。Esc、空行回车或卡片失去焦点时结束，已输入的文字会保留，和退出编辑一样。整个过程算一个操作组。输入期间卡片按“正在编辑”处理：原地不动，只往空处长高。
- **清单的派生显示**（都不写库）：已勾选 ≥ 3 项、并且还有未完成项时，已勾选项连同子项折叠成一行“已完成 N 项”；全部勾完时 ○ 高亮并常驻，但不会自动完成卡片；胶囊显示下一项（`Card.NextTask`），标题本身就是某个任务时，直接用下一项代替标题。
- **快速记录**：用热键或 + 新建的卡片，按 Esc 后焦点回到之前的程序。

## 5. 布局

- `Layout.Tile` 是纯函数，有单元测试。它按列排列，列宽取该列最宽的卡片，卡片贴列的外侧边缘对齐，固定间距 G=12 DIP、边距 16 DIP。
- **顺序**：有提醒的按时间在前；其余按 `Card.Rank` = `ord ?? created_at` 由大到小。拖动平铺的卡片时（`WM_MOVING`），对它所在显示器的队列逐个试插入位置，算出它在每个位置会得到的矩形；与卡片相交且中心最近的位置就是落点，其他卡片按这个落点让位，没有相交的位置时队列合拢、松开后卡片成为自由卡片。松开时把这些卡片原有的 rank 按新顺序从大到小重新分配（`Card.Ranks`，保持严格递减），所以只有被越过的卡片写库，整次拖动一组撤销。有提醒的卡片不能越过。
- 避让：自由卡片、+ 按钮和速拨区、正在编辑/撤销/临时展开的卡片都是障碍物，每个障碍物都会按 G 向外扩大。
- **从不层叠**。放不下时，从排序末尾开始把卡片显示成胶囊（只影响显示，不写库）；还放不下就隐藏，+ 上显示 +N。到期的卡片排在最前，永远不会被隐藏。
- 鼠标停在某块屏幕的卡片上时，暂缓这块屏幕的自动重排，鼠标离开后再补做。新建、“平铺”、缩放图片、撤销这类用户直接操作会立即执行。卡片内侧 6 DIP 的缩放边框属于非客户区，WPF 会在那里报告 MouseLeave，所以离开以指针下的窗口（`WindowFromPoint`）为准。
- 布局按显示器分三遍：+ 按钮和自由卡片（互相推开，只影响显示）→ 正在编辑/撤销/临时展开/临时拉宽/被拖动或缩放的卡片（原地不动，长高时遇到障碍物就停；拖动中的平铺卡片除外）→ 其余卡片按显示顺序平铺，拖动中的平铺卡片只占住它的落点。
- 自由卡片之间以及和 + 之间用 `PushOut` 推开：拖放时写入推开后的位置；其他时候只影响显示。

## 6. 提醒

- 只有一个 `remind_at`，用 UTC 毫秒存储，不设单独的截止日期，也不做重复提醒。
- 每秒一次节拍：每个 `(卡片, remind_at)` 到期后**只响一次**，无论这个时间是怎么来的（预设、稍后提醒、CLI、一个已经过去的时间）。启动时已到期的卡片一起响一次。从睡眠恢复、系统时间改变时立即补一次节拍。提醒面板拒绝已经过去的时间。
- “到期”是派生状态：到期卡片置顶、展开、始终可见（即使桌面被最小化），直到改期、清除或完成。不需要任何回滚代码。
- 预设直接显示具体时刻（例如“明天上午 · 周四 09:00”），“下周一”一定是周一。输入框支持中英文的相对和绝对时间（见 `When.Parse`，有单元测试）。

## 7. LLM 与抓取

- **配置**（各项互相独立，改动立即生效）：`llm.where` = windows | wsl；`llm.tool` = 表中的工具、custom 或空（关闭）；`llm.distro` = WSL 发行版（空为默认）；`llm.model`；`llm.custom` = 自定义命令行（Windows 由 cmd.exe、WSL 由 `bash -c` 执行，放在同一个 timeout 之下）；`llm.env` = 从该发行版登录 shell 取得的 PATH/代理。Windows 工具每次按当前 PATH 查找，不存路径。首次启动自动检测一次（`llm.detected`），之后由设置页决定；设置页的“检测”只查所选环境（WSL 报错原样显示，例如发行版不存在）。
- **执行器是数据**（`agents/<名字>.json`；内置的 claude、codex、gemini、qwen、llm、ollama 在仓库 `builtin/agents/`，嵌入 exe；同名用户文件覆盖内置）。一份执行器给出：常量参数 `args`（`{model}`、`{grants}` 必须是完整的一项）、模型怎么传（`model`，`{value}`）、是否必须有模型、检测顺序 `priority`、列模型的参数，以及**授权对照表** `grants`：把抽象授权翻译成这个 CLI 自己的参数。
  - `none`：只做文字处理，不开任何工具（claude：`--tools ""`）
  - `web`：只允许 WebFetch/WebSearch，`--permission-mode dontAsk`，限制轮数
  - `read`：只允许 Read，在文档所在文件夹里运行、提示词写明文件名；`--setting-sources user`，所以那个文件夹里的 `.claude` 设置和 hooks 不会被加载
  - `shell:<命令前缀>`：只允许以该前缀开头的命令（claude：`Bash(<前缀>:*)`）；前缀只能含字母数字空格和 `. + / \ : = @ , ~ -`
  - 一次运行需要几个授权就按顺序拼接各自的参数（claude 的 `--tools` 重复出现会累加，已实测）；执行器没有的授权 = 这个执行器不能跑需要它的技能。自定义命令只支持 none。
  - 内置执行器的参数与原来写死的表逐项相同，所以行为没变（原有测试原样通过）。新 CLI = 新文件，不改代码。
- **WSL**：`wsl.exe [-d <发行版>] --cd <文件夹|~> -e [/usr/bin/env PINCC_PATH=… 代理变量…] bash -lc <常量脚本> <工具> <参数…>`。bash 只看到一段常量脚本（`exec timeout -k 5 170 "$0" "$@"`），工具和参数作为 `$0 "$@"` 传入，所以路径里的引号、`$()`、反引号都只是普通字符。检测时读取用户登录 shell（包括 zsh）的环境，只保留 PATH、NVM_BIN、代理等白名单变量，运行时通过 `env` 传入；这样 nvm 装在 `~/.bashrc` 或 `~/.zshrc` 里的工具也能找到。
- **进程调用**：
  - 提示词整段走标准输入，由后台任务写入后立即关闭；命令行参数里不包含任何用户内容
  - 超时从启动时开始计算，覆盖写标准输入的过程；超时后结束整棵进程树
  - stdout/stderr 按字节读取，按 BOM → 严格 UTF-8 → GB18030 解码（cmd.exe 的 GBK 报错也能读懂），stdout 有上限
  - 子进程放进带 `KILL_ON_JOB_CLOSE` 的 Job，PinCC 崩溃或退出时一并结束
  - `.cmd` 包装（npm 安装的工具）通过 `cmd.exe /d /s /c` 启动，参数固定；路径含 `"` `%` `!` 时拒绝
  - 模型名必须匹配 `^[A-Za-z0-9][A-Za-z0-9._:/@-]{0,63}$`，否则忽略，不可能被当成参数
- **提示词**：模板占位符一次替换（标题里出现 `{content}` 也只是文字）；内容里的 `</document>`、`</meta>` 被中和；正文按上限截断。
- **结果校验**：退出码为 0 且有输出才算成功。写入前在同一个事务里核对来源和输入哈希，不一致说明卡片已经改动，丢弃这次结果。同一张卡片同一时间只跑一个，全局最多同时跑 2 个。
- **抓取**（一次 15 秒的总期限，覆盖响应头和正文；下载文件时放宽到 60 秒），先看 Content-Type 再读正文：
  1. HTML：Edge 的 UA；最多 2 MB；编码按 BOM → 响应头 → `meta charset` → 严格 UTF-8 → GB18030 判断；从 JSON-LD 的 articleBody、常见站点的正文容器、`<article>`/`<main>`/`<body>` 中提取正文；没有描述时取正文开头约 160 字
  2. 图片（按文件头校验，最多 15 MB）：卡片直接变成这张图片
  3. PDF / Word / PowerPoint / Excel（按文件头校验，最多 25 MB）：存到 `files\`；Office 文档自己提取文字，PDF 交给 LLM 的 file 模式
  4. 正文不到 300 字时，调用 Edge 无头模式的 `--dump-dom` 再提取一次（一次只跑一个 Edge）
  5. 仍然不够，让 LLM 在 url 模式下自己读
- **隐私**：只有公网 http(s) 地址才会被**自动**读取：域名解析出的每个地址都必须是公网地址，不能带 `user:pass@`，参数名里不能有 token/key/secret/sig/code 之类。自动读取时每一次跳转都重新检查，公网链接跳到内网地址就停下，改为等用户点 ✨（用户主动要求时照常跟随跳转）。
- **文件卡片**跟随文件：每 15 秒比较一次大小和修改时间，变了（或文件被删除）就重新读取，旧摘要标为过时。

### 7.1 技能

原则：代码只保留安全契约和执行管线；“什么时候、先取什么数据、允许模型做什么、结果写到哪里”都写在技能文件里。飞书、别的 CLI、别的 LLM 都不在代码里出现。

- **格式**：`skills/<名字>/SKILL.md`，与 Claude 的技能格式相同：`---` 之间是元数据，正文是提示词。元数据每行 `键: 值`，值是普通字符串或一段 JSON（可以跨多行缩进；JSON 本身是合法 YAML），`#` 开头的行是注释，不认识的顶层键忽略（其他 agent 的 license 等字段可以共存）。解析失败的文件不生效，原因显示在设置页和 `PinCC skills`。
  - `name`、`description` 必填；`label` 是菜单和 ✨ 上的短名
  - `when`：`src`（通配符，匹配网址或文件路径）、`kind`、`ext`、`tag`、`scope`（card / desk）、`on`（ask = ✨ 和右键菜单；create = 新建或来源变化时自动；menu = 只进菜单）
  - `context`：模型运行前 PinCC 自己执行的取数步骤，输出拼成 `{content}`：`{"run": [程序, 参数…], "where": runner|windows|wsl, "timeout": 秒}`，或内置读取 `{"builtin": "source" | "note" | "desk"}`
  - `grants`（web、read、pincc、`shell:<前缀>`）、`runner`（偏好的执行器）、`output`（summary / append / cards / none）
- **选哪个技能**：条件全部满足才算匹配；具体度 = src 4 + ext 3 + tag 2 + kind 1，同分时用户技能优先。✨ 和自动运行都交给具体度最高的那个，再看它的 `on` 是否允许。所以一个只允许 ask 的飞书技能，也会挡住内置摘要对飞书链接的自动运行（那只会读到登录页）。自动运行只对 output=summary 的技能生效，条件和内置摘要一样：没有摘要或摘要过时。卡片右键“技能 ›”列出所有匹配的技能；桌面技能在 + 的右键菜单里。
- **内置摘要也是一个技能**（`builtin/skills/summary/SKILL.md`，正文就是默认模板）：它的取数步骤 `builtin: source` 就是原来的读取级联（HTTP → Edge 渲染 → 让模型用 web 自己读；文档：自己提取文字 → 让模型用 read 读）。原来的行为不变：链接和文档自动，笔记点 ✨，隐私守卫照旧。
- **取数步骤**与模型用同一套进程规则：参数是独立的项；占位符 `{src} {file} {dir} {card} {title}` 替换后仍是一项；WSL 里经固定包装脚本及独立的运行编号、预算参数；取消时清理对应进程组，阶段期限取声明上限与整体剩余预算的较小值；Windows 的 .cmd 包装经 cmd.exe 时，含 `" % !` 或换行的参数拒绝，含空格或 `& | < > ^ ( )` 的加引号。退出码非 0 时技能失败，并显示那个程序自己的错误。
- **环境变量契约**：每次运行（模型和取数步骤）都带 `PINCC_CARD`、`PINCC_SRC`、`PINCC_FILE`、`PINCC_DIR`、`PINCC_SKILL`、`PINCC_EXE`、`PINCC_HOME`（仅当设置了），有 pincc 授权时再带 `PINCC_GROUP`。名字必须以 `PINCC_` 开头，值不能含控制字符。WSL 里路径转成 `/mnt/…`，经 `/usr/bin/env` 参数传入，另设 `WSLENV=PINCC_GROUP:PINCC_HOME`，让模型在 WSL 里调用的 PinCC.exe 也能拿到。
- **一次运行 = 一个操作组**：需要 pincc 授权时，先写一条标记记录（op=run，card_id=0）取得组号，作为 `PINCC_GROUP` 传给模型；命令行看到它、并且库里确实有这条标记时，本次写入并入该组。撤销这一组就撤销整次运行，标记记录恢复时什么也不做。已实测：WSL 里的 claude 调用 Windows 的 PinCC.exe，写入进了预留的组，`restore` 一次撤销。给模型的说明要求每条命令都以 PinCC 的完整路径开头，因为 claude 只放行这个前缀（实测：模型先读 help 后改用短名，就被拒了）。
- **确认**：用户技能如果有 run 步骤或授权，在桌面上第一次运行前弹窗，列出将执行的命令、授权和文件位置。确认结果记为 `skill.ok.<名字>` = SKILL.md 的哈希，内容一改就要重新确认；没确认的技能不会自动运行。命令行 `PinCC run` 是用户亲自发起的，不再确认。
- **运行记录**：数据目录 `runs.log`，一行一个 JSON（时间、技能、卡片、执行器、授权、耗时、结果）；`ms` 保留原有模型阶段（含模型排队）含义，不改成总耗时。超过 1 MB 时只保留最后 500 行。GUI/CLI 追加和轮转用按 Home 命名的跨进程互斥，有限等待，唯一临时文件，写失败不阻断业务。
- **阶段诊断**：`diagnostics.log` 是独立的 schema=1 JSONL，含版本、PID、UTC、run_id 和阶段 start/end/terminal；从预读取开始记录，正文和完整提示词不写入。意外中止时最后阶段只是定位线索，不足以单独证明卡死原因。
- **任务生命周期**：GUI 预读取和 CLI 运行共用 RunContext 的单调截止时间；默认预算按取数步骤与模型上限推算，`llm.run_timeout`（1–86400 秒）可覆盖。排队有期限，取消和截止不会触发读取回退；模型与取数步骤保留独立阶段上限。回写检查取消、输入/正文变化及卡片状态，迟到回调不能清除新任务状态。
- **解析限制**：HTML 正则设置匹配超时并检查整体解析期限；Office 限制条目、累计解压字节和输出文本，采用有界流读取；ZIP64 文档交由已授权的读取回退。同步工作另设有限并发，传入 token 并检查实际循环，不能把 Task.Run 的取消当成已停止读取。
- **故障收敛**：全局 WPF 异常处理有重入与退出状态，故障提示不依赖 WPF；应急编辑和快捷添加草稿通过独立存储连接保存，恢复 key 与卡片同事务提交防止重复恢复。正常渲染失败不再被误判为数据库保存失败；退出和资源释放幂等。
- **后台维护**：清理、备份、文件状态与配置扫描不占 UI 线程；维护连接与 UI 连接分离。图片引用写入和回收协调，复用图片在提交引用前更新租期。清理分批且 SQL 有截止时间，备份仅成功后替换正式副本。
- **字体回退**：等宽字体候选在首次使用时检查 Normal/Bold 的字体匹配和离屏测量。不可用候选排除并记录 HRESULT，避免系统 family 名解析失败阻止后续字体回退。
- 文件改动几秒内自动重新读取；设置页“技能与执行器”列出生效的技能、执行器和错误，可以打开两个文件夹、重新加载、复制给其他 agent 用的 SKILL.md（同 `PinCC help --skill`）。示例：`docs/examples/skills/feishu-doc`（用 lark-cli 读飞书文档，在执行器所在的环境里运行，只在 ✨ 时运行）。

## 8. 热键

- 默认只绑定“新建卡片”：**Ctrl+Alt+Shift+N**。Word/WPS 的 Ctrl+Alt+V/C/N/T 这类应用内快捷键，`RegisterHotKey` 会成功注册并直接抢走，无法检测冲突，所以不选这类组合。其余四个动作默认不绑定，需要时自己设置。
- 设置页录入快捷键时，会暂停全部全局热键、关闭输入法，并装一个低级键盘钩子（`WH_KEYBOARD_LL`），在其他程序的热键和钩子之前拿到组合键，所以别的程序已经占用的组合也能录入并被报告（Alt+Tab 照常切换窗口；Esc 只退出录入框，不关闭窗口）。检测结果如实显示为“已注册”或“被占用（1409）”；两个动作绑定同一组合时显示“与「X」重复”，不会误报成别的程序占用；并对照一张已知冲突表提示：Word/WPS、QQ、微信、OneNote、便笺、PowerToys、输入法、Snipaste、F12。

## 9. 取舍

- **采纳的调研建议**：
  - 窗口矩形就是卡片（去掉阴影边距，避免透明像素挡住点击）
  - 底部一行合并“状态”和“操作”（不遮挡首行）
  - 卡片原地撤销
  - 放不下时变成胶囊，不层叠
  - 每个显示器单独的置顶设置
  - + 悬停速拨
  - 热键默认只绑一个
  - 列级差量写 + rev
  - 操作组撤销
  - Job 对象管理子进程
  - 隐私守卫
  - 摘要过时检测
  - 每日备份
- **与评审建议有出入的地方**：
  - 保留了常见中文站点的正文容器规则。成本低，对中文用户收益高。
  - 编辑时卡片只会变高，不会变矮；变高时按障碍物处理，其他卡片让开。
  - 通知使用贴在 + 旁边的小提示条，这个位置不会有卡片。
- **不做**：见 README 的“刻意不做的事”。
