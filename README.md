# Pin Carbon Copy（PinCC）· 桌面悬浮卡片

正式全称 **Pin Carbon Copy**；**PinCC** 是简写，也是命令名、程序集名与数据目录名（`PinCC.exe`、`pincc`、`%LOCALAPPDATA%\PinCC` 等均不变）。

每张卡片就是一件待办：备忘、清单、网址、文档或一张图片。每张卡片都是一个独立的无边框小窗口，可以置顶，也可以按正常层级显示。卡片自动平铺、互不重叠，也能拖到任意位置。网页和文档会自动读取正文，交给本机的 CLI LLM（claude / codex / gemini / ollama…，也支持 WSL 里的）生成摘要。所有内容存放在本地 SQLite，任何操作都能撤销；同一个 exe 还提供命令行文本接口，供 LLM 工具读写卡片。

- **技术**：C# / WPF / .NET 10，**零 NuGet 依赖**。SQLite 使用 Windows 自带的 `winsqlite3.dll`；截图、浏览器、文档查看、提示音、网页渲染都交给系统和现有程序完成。
- **发布**：单文件 exe。可选框架依赖版（几 MB），或自带运行时的独立版。
- **适配**：Windows 10 1903+ / Windows 11；按显示器 DPI 感知（PerMonitorV2），支持混合缩放、负坐标的多显示器。

## macOS 本地工程

Mac 版采用 Swift 6、AppKit 和系统 SQLite，每张卡片仍是独立悬浮窗口。完整源码与 Xcode 工程位于 [mac/](mac/README.md)，使用 Xcode 16 或更新版本，部署目标 macOS 13。开发、双架构检查、helper 和本地/正式发布入口见 [Mac 工程说明](mac/README.md)；实现依据与实机验收见 [实现记录](docs/MACOS-IMPLEMENTATION.md)。

## 快速上手

| 你想… | 这样做 |
|---|---|
| 新建卡片 | 点屏幕角落的 **+**，或按 **Ctrl+Alt+Shift+N**（可在设置中更换） |
| 从剪贴板 / 文件建卡 | 把文件、链接、图片、文字**拖到 +** 上；或右键 + →“用剪贴板新建” |
| 截图贴到桌面 | 用 Win+Shift+S（或 QQ/微信截图）截图，再**点 +**，直接得到一张 1:1 悬浮图片。同一次复制只贴一次，再点 + 就是空白卡片；在编辑中的卡片里按 Ctrl+V 也能贴图 |
| 编辑 | **双击文字**（光标落在点击处），或选中卡片按 **Enter** |
| 结束编辑 | 点卡片外任意处，或按 **Esc**。两种方式都会自动保存，**没有“完成”按钮** |
| 完成一件事 | 悬停卡片，点右下角的 **○**。卡片原地收成“已完成 · 撤销”，鼠标离开 4 秒后消失（在它上面按 Ctrl+Z 也能撤销） |
| 清单加一项 | 点底部的 **☑ 2/5**（悬停时显示 ＋），底行变成输入框：输入后回车，可以接着输入下一项；Esc 或点卡片外结束。粘贴多行文字会一行加一项 |
| 一键平铺 / 折叠 / 最小化 | **悬停 +**，弹出三个按钮；或右键 + 选择。平铺不会展开你折叠的卡片 |
| 置顶 / 透明度 | 悬停卡片点 **📌**；置顶卡片上 **Ctrl+滚轮** 调透明度（20–100%），鼠标移上去会恢复不透明 |
| 本屏全部置顶 | 右键该显示器的 + →“本屏卡片置顶”，之后在这块屏幕上新建的卡片也会置顶 |
| 提醒 | 悬停卡片点 **⏰**：“1 小时后”“今天下午/今晚”“明天上午”“下周一”，或直接输入 `18:30`、`明天 9点`、`周五下午3点`、`9/25 14:00`、`+30m` |
| 撤销 | 在卡片上按 **Ctrl+Z**，或右键 + →“撤销”；更早的记录在 **管理 › 卡片** 中逐条恢复 |
| 找回卡片 | 右键 + →“管理…”（卡片上按 Ctrl+F 也能打开）：搜索全部活动、已完成、已删除的卡片 |

### 卡片的样子

- **没有标题栏**。卡片底部只有一行：左边显示已设置的状态（📌 置顶、⏰ 提醒时间、☑ 2/5 任务进度、✨ 摘要），右边的操作按钮只在悬停时出现：⏰ 📌 ● 颜色、⌃ 折叠、○ 完成。
- **没有滚动条**。内容放不下时，还有内容的一侧淡出，在卡片上**滚动鼠标滚轮**即可上下查看；也可以拉大卡片，或点 ✨ 让 LLM 生成一段适合卡片大小的摘要。清单放不下时每项只占一行（过长的末尾省略），能看到更多项。
- **临时拉宽**。拉宽没有置顶的卡片只是临时的：卡片激活（点过它）期间保持，切到别处后恢复原来的宽度。滚动位置也一样：卡片没有置顶、也没有激活时，鼠标离开就回到开头。置顶的卡片拉宽后记住新宽度，滚动位置也保持。
- **高度自适应**。卡片默认按内容自动长高（最高约 40% 屏幕高），拉动边缘改高度后就固定下来；**双击下边缘**恢复自适应。
- **链接卡片**：网站 · 域名 · 日期、标题、摘要（生成前先显示网页描述），然后是你自己的备注。
- **文档卡片**：类型 · 大小 · 修改时间 · 所在文件夹，以及开头的正文或摘要。
- **图片卡片**：只有一张图片、没有文字时，整图无边框悬浮，初始为 1:1 像素大小（最大半屏）。滚轮缩放，中键恢复 1:1，Ctrl+拖动可把图片拖进其他程序；悬停时操作按钮浮在图片底部一条深色圆角底板上，什么图片上都看得清；折叠后变成缩略方块。多张图片显示为一排缩略图。网址本身是图片时，卡片直接变成这张图片。
- **Markdown**：`#` 标题、**粗体**、*斜体*、~~删除线~~、`代码`、链接、`> 引用`、代码块、列表。点击 `- [ ]` 任务前的方框就会勾选，只改写这一行。
- **清单**：已勾选达到 3 项、并且还有未完成项时，已勾选的项折叠成一行“已完成 N 项”，点它展开或收起（只影响显示）。全部勾完后，右下角的 ○ 高亮并常驻，点一下就完成整张卡片（不会自动完成，清单也可以当模板反复用）。折叠成胶囊时显示下一项，例如“周末 · 买菜”。
- **到期提醒**：卡片自动显示、展开、置顶，红框闪三下后保持红色，并响一声。卡片上直接有“10分钟”“1小时”“○”三个按钮。全屏游戏、视频或演示时先不打扰，结束后再提醒。

### 布局

- 卡片默认从右上角（可在设置中换角）按固定间距竖排平铺，排满一列再换下一列。卡片之间、卡片与 + 按钮之间**绝不重叠**。
- **拖动排序**：拖动平铺中的卡片时，其他卡片在离它最近的位置让出空位，松开就插入那里（也可以拖到另一块屏幕的队列里）。设置了提醒的卡片按时间排，不参与调整。
- 拖离平铺队列再松开，卡片就记住自己的位置，其他卡片会绕开它；放下时如果压住别的卡片，会被自动推开。右键 →“回到平铺”可让它重新参与平铺。
- 屏幕放不下时，排在后面的卡片先变成一行“胶囊”；胶囊也放不下时暂时隐藏，+ 上显示 **+N**。点击胶囊可以临时展开。
- 排序：设置了提醒的卡片按时间由近到远排在前面（已到期的最前），其余按创建时间由新到旧；拖动排过的卡片按你排的位置。
- 每个显示器各有一个 +，位置按“屏幕角 + 固定内边距”计算，所以换分辨率、换缩放比例、插拔显示器都不会跑偏。把 + 拖到别的角即可换位置。

### 颜色

七种等明度的浅色（柠檬、天空、蔷薇、薄荷、丁香、蜜桃、湖水），另有两种只能手动选的颜色（云灰、墨炭）。**新卡配色**可以设置为：

- 关：统一一种颜色
- 轮换：每张新卡按顺序换一种颜色，相邻两种的色相相差较大（新建时 + 按钮就显示下一张的颜色）
- 按类型：笔记、清单、链接、文档、图片各一种颜色
- 按 #标签：同一个标签同一种颜色

右键 + 或在设置里随时切换，已有卡片会立即重新配色。自己手动选过颜色的卡片不受影响。红色只用来表示到期。

## AI 摘要（本地 CLI LLM）

第一次启动时，PinCC 会自动查找可用的工具：先找 Windows 里的 claude、codex、gemini、qwen、llm、ollama（以及你自己添加的执行器），再找 WSL 里的。找到后，**新建链接或文档卡片**时会自动读取正文并生成摘要；**笔记**只有在你点 ✨ 时才摘要。

之后可以在 **管理 › 设置 › AI 摘要** 里自己选：

| 设置 | 说明 |
|---|---|
| 运行环境 | **Windows** 或 **WSL**；WSL 可以指定发行版（留空用默认发行版） |
| 工具 | 关闭 / claude / codex / gemini / qwen / llm / ollama / **自定义**。点“检测”会在当前环境里查找，找到的标 ✓ |
| 模型 | 可选，例如 `sonnet`、`gpt-5.1`；ollama 必须填 |
| 自定义命令 | 任意命令行：Windows 下由 cmd.exe 执行，WSL 下由 bash 执行。约定：**从标准输入读取提示词，把回答输出到标准输出**，例如 `ollama run qwen2.5 --nowordwrap`。只用于文字处理（让模型自己读网页、读 PDF，需要有 web / read 授权的执行器，例如 claude） |

“测试”会用当前设置实际运行一次；下方显示实际执行的完整命令。改动立即生效。

- **提示词**：整段通过标准输入传入，命令行参数中不包含任何卡片内容。摘要默认用简体中文输出：第一行是一句话结论，然后是 3–6 条要点，需要你去做的事单独列在最后。长度按卡片大小估算，尽量不溢出。提示词模板可以在设置中修改。
- **读网页**：先用 HTTP 读取（识别 GBK/GB18030 编码、JSON-LD 和常见站点的正文容器，如微信公众号、知乎、CSDN、GitHub）。读不到正文时（例如纯 JavaScript 渲染的页面），调用系统自带的 Edge 无头渲染一次。仍然不行时，让 claude 用 WebFetch 自己去读。网址本身是图片时，卡片直接变成这张图片；是 PDF/Office 文件时，先下载再按文档处理。
- **读文档**：txt/md/代码/csv/json、docx/pptx/xlsx 由 PinCC 直接提取文字；PDF 等其他格式让 claude 在文档所在文件夹里用 Read 工具读取（只开放 Read，不加载那个文件夹里的 `.claude` 设置）。文档改动或被删除后，卡片会在 15 秒内更新，旧摘要标为过时。
- **隐私**：只自动读取公网地址。内网地址、localhost、解析到内网的域名、带账号密码或 token/key/sig/code 这类参数的链接，都不会被自动抓取和发送；自动读取时如果跳转到了内网地址也会停下。这些情况需要你手动点 ✨。
- **过时提示**：卡片内容改动后，摘要会变淡，并重新出现 ✨；结果回来时如果内容已经变了，这次结果直接丢弃。

### 技能与执行器：让 LLM 用上别的工具和流程

摘要只是内置的一个**技能**。技能和**执行器**都是数据目录里的普通文件，添加一个文件就多一种能力，不需要改程序：

- **执行器** `agents\<名字>.json`：怎样调用一个 CLI 模型（参数、模型怎么传），以及它能被授予什么：`web`（自己上网读）、`read`（读文档所在文件夹）、`shell:<命令前缀>`（只允许以这个前缀开头的命令）。内置 6 个，同名文件覆盖内置的。
- **技能** `skills\<名字>\SKILL.md`（与 Claude 的技能格式相同）：什么卡片用它（网址/路径通配、类型、扩展名、#标签，或者整个桌面）、什么时候跑（✨、自动、只在菜单里）、先运行什么程序取数据（比如 `lark-cli`、`pdftotext`，可以在 WSL 里）、允许模型做什么、结果写到哪里（摘要、追加到正文、新建卡片，或者由模型自己调用 PinCC 命令行写回）。正文就是提示词。

```text
---
name: feishu-doc
label: 飞书文档
description: 用 lark-cli 读取飞书云文档正文，再压缩成卡片摘要
when: {"src": ["https://*.feishu.cn/*", "https://*.larksuite.com/*"], "on": ["ask"]}
context: [{"run": ["lark-cli", "docs", "+fetch", "--doc", "{src}", "--doc-format", "markdown"], "where": "wsl", "timeout": 90}]
output: summary
---
把 <document> 里的飞书文档压缩成便签卡片上的摘要……
```

- 飞书链接卡片上的 ✨ 会变成“✨ 飞书文档”；其他卡片照旧是摘要。条件越具体的技能越优先。卡片右键“技能 ›”可以选别的技能，桌面技能（例如按全部卡片排出今日计划）在 + 的右键菜单里。
- 会运行程序或授权模型的技能，**第一次运行前会弹窗确认**（列出命令和授权）。之后文件一改，就会再确认一次。
- 授权 `pincc` 时，模型可以自己调用 PinCC 命令行加卡片、加任务、写摘要。这次运行的所有写入算一个操作组，Ctrl+Z 或 `PinCC restore` 可以一次撤销。
- 每次模型调用的完成摘要记录在数据目录的 `runs.log`，取数、排队、模型执行、回写和终态另记在 `diagnostics.log`，通过 `run_id` 关联。日志不记录正文或完整提示词。
- 任务从取数开始计入总预算，排队也计时；模型仍保留 Windows 150 秒、WSL 180 秒阶段上限。可通过数据库设置 `llm.run_timeout`（1–86400 秒）覆盖自动计算的总预算；默认兼容技能声明的长取数步骤。处理中可取消，命令行 `run` 支持 Ctrl+C；取消或过期的结果不再写回。
- 设置页“技能与执行器”显示生效的技能、执行器和文件错误。示例在 `docs/examples/skills`。

## 命令行：给人和 LLM 工具的文本接口

同一个 `PinCC.exe` 带参数运行时就是命令行。桌面程序会在 1 秒内反映命令行做出的修改。

```text
PinCC list [--all] [--json|--md]        列出卡片（排序与桌面一致）；--md 输出为一篇完整的 Markdown
PinCC show <id> [--json]                查看一张卡片
PinCC add <文字|-> [选项]                新建卡片；正文第一行是网址或文件路径时就是链接/文档卡片
PinCC set <id> [文字|-] [--append] [选项] [--check N] [--uncheck N] [--if-rev N] [--if-input H]
PinCC rm <id> [--json]                  删除（可恢复）
PinCC log [N] [--json]                  最近的操作（第一列是操作组编号）
PinCC restore <组编号> [--json]          撤销整组操作（只写回这组改过的内容）
PinCC skills [--json]                   列出技能和执行器（含文件错误）
PinCC run <技能> [<id>] [--json]         运行一个技能并按它的 output 写回
PinCC help --skill                      输出一份教其他 agent 使用 PinCC 的 SKILL.md
PinCC help                              完整说明（面向 LLM 工具）

选项：--summary <文字|->  --remind <时间|off>  --done | --undone  --color <0-8|auto>  --top | --normal  --image <图片文件>  --json
      --add-task <文字|->（每行一项，加在最后一个任务之后）  --check / --uncheck N（第 N 个任务，可写 1,3；序号见 show --json 的 tasks）
退出码：0 成功 · 1 用法错误（含未知选项、标准输入为空）· 2 找不到 · 3 冲突（--if-rev / --if-input 不符，未写入）· 4 数据库忙
```

示例：

```bash
# 在 WSL 里让 claude 汇总今天的待办
/mnt/c/Tools/PinCC/PinCC.exe list --md | claude -p "按优先级给我今天的行动清单"

# 给一张卡片写回摘要（仅当摘要的输入没变时写入；期间内容改了则退出码 3、不写入）
PinCC show 12 --json            # 读取 input_hash
PinCC set 12 --summary - --if-input 3F2A9C0B1D4E5F60 < summary.md

# 清单：加一项、勾掉第 2 项（只改那一行，不覆盖别处的改动）
PinCC set 7 --add-task "买牛奶"
PinCC set 7 --check 2

# 新建带提醒的待办
echo "- [ ] 提交周报" | PinCC add - --remind "周五 17:00"
```

- `-` 表示从标准输入读取（UTF-8）。管道中输出 UTF-8，在交互式 cmd/PowerShell 中输出 UTF-16，不会改动你的代码页。
- 在 cmd 或 PowerShell 里交互使用时，它们不会等待 GUI 程序结束，输出会出现在下一个提示符之后。需要等待时可以用 `start /wait PinCC.exe list`，或者接管道：`PinCC list | more`。
- 从 WSL 调用时，请通过 `PinCC.exe` 访问，**不要直接打开数据库文件**：SQLite 的 WAL 模式不能跨 WSL 文件系统共享。
- 设置里可以把 PinCC 加入 PATH，这样终端和 WSL 都能直接运行 `PinCC.exe`。

## 数据与恢复

- 数据目录：`%LOCALAPPDATA%\PinCC`（可以用环境变量 `PINCC_HOME` 指定其他位置）
  - `pincc.db`：SQLite（WAL 模式）
  - `img\`：粘贴或拖入的图片，按内容哈希命名
  - `backup\`：每天自动备份一份，保留 7 份；后台先写临时文件，成功后替换正式备份
  - 恢复草稿：优先写入 `%LOCALAPPDATA%\PinCC\recovery-fallback\`，不可用时写入数据目录的 `recovery\`；下次启动按版本恢复，遇到并发修改保留草稿，避免覆盖新内容
  - `error.log`：未处理异常；`diagnostics.log`：版本、PID、任务阶段及故障信息
- **每次修改都会记录**：一次手势（一次编辑、一次拖动、一次“全部平铺”、一条 CLI 命令）是一组操作，可以整组撤销。撤销只写回这组操作改过的字段，之后别处的修改（例如 CLI 写入的摘要）不受影响。撤销本身也是一组操作，所以撤销也能再撤销。
- 删除的卡片和操作记录保留 30 天（可设为 7/30/90/365 天）。完成的卡片一直保留，作为“已完成”归档。
- 首次运行会设为开机启动（写入 `HKCU\…\Run`），可以在设置中关闭。

## 构建

**依赖（不进仓库）**：零 NuGet；构建只需本机 [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0)；框架依赖版运行还需 [.NET 10 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/10.0)。也可用：

```bat
winget install Microsoft.DotNet.SDK.10
winget install Microsoft.DotNet.DesktopRuntime.10
```

`build.cmd` 会先检查 SDK / Desktop Runtime，再继续构建。系统自带的 `winsqlite3.dll`、可选的本机 CLI LLM（claude / codex / …）都不打包进仓库。

```bat
build.cmd
```

脚本先运行模块及隔离集成测试（`tests/`，无需任何测试框架），在临时目录发布两个版本，再对真实发布程序进行隔离的 WPF 生命周期测试。全部通过后才替换正式产物；替换失败回滚，成功后自动清理临时文件：

- `dist\PinCC.exe`：框架依赖的单文件版（约 1 MB），需要安装 .NET 10 Desktop Runtime
- `dist\standalone\PinCC.exe`：自带运行时的单文件版（约 60 MB）

正式产物用 Git LFS 存档（见 `.gitattributes`）；`bin/`、`obj/`、`.probe/`、诊断转储等中间文件不入库。

开发时可以用 `dotnet run --project src` 直接启动。只运行模块及集成测试可用 `dotnet run --project tests -c Release`；已发布程序的 UI 回归可用 `powershell -NoProfile -File tests\UiSmoke.ps1 -Executable <PinCC.exe绝对路径>`。UI 测试使用独立数据目录与实例身份，覆盖正常编辑退出、布局异常、通知异常、退出清理异常及数据库保存失败，验证草稿、异常隔离及进程退出；成功自动清理，失败保留证据路径。设置 `PINCC_TEST_WSL=1` 可同时验证本机 WSL 的超时、取消与子进程清理。

诊断：设置 `PINCC_SNAPSHOT=<目录>` 后启动，程序会在屏幕外把每张卡片渲染成 PNG，把显示器信息和窗口的物理坐标写入 `layout.json`，然后退出。锁屏时也能检查渲染和布局。

**借鉴了什么**：

- 微软便笺：没有标题栏、首行即标题、操作按钮悬停才出现、浅色配色加一个深色、粘贴时记录来源网址
- To Do：只有一个提醒时间（不分截止日期和提醒）、预设显示具体时刻、下周一固定是周一、多档稍后提醒、按完整时间戳排序、完成时是一个圆圈
- Snipaste / PixPin：Ctrl+滚轮调透明度、图片悬浮后可缩放和拖出、找回屏幕外的卡片
- Zhorn Stickies / macOS 便笺：折叠成一行
- jcconsult/sticky-notes：勾选任务只改写这一行
- ddakji / Zhorn / Mint：提供外部文本接口

**刻意不做的事**：所见即所得编辑器、占用屏幕边缘的停靠栏、全屏覆盖窗口、失焦自动折叠、反复强行置顶、双击关闭、单字母快捷键、完成音效、星标、“我的一天”、重复提醒、在正文里识别日期、点击穿透、OCR、MCP、窗口动画、磁吸吸附、托盘图标。

## 目录

```text
src/Program.cs          入口：带参数 = 命令行，不带参数 = 桌面程序（单实例）
src/Core/               纯逻辑：Db（winsqlite3）、Store（修改与操作记录）、Card（派生状态）、Cli、
                        When（时间解析）、Markdown、Fetch（网页/文档）、Llm、Agents（执行器）、Skills（技能管线）、
                        Proc（子进程与 Job）、RunContext（截止时间与阶段）、Diagnostics（并发安全日志）
builtin/                随程序发布的执行器（agents/*.json）和技能（skills/*/SKILL.md），与 Mac 版共用
src/UI/                 WPF：Desk（唯一的修改入口与布局）、CardWindow、HubWindow（+ 按钮）、ManageWindow、
                        Flyout（提醒/颜色）、Layout（纯函数）、Native（Win32）、Hotkeys、MarkdownView、Theme.xaml
mac/                    macOS Swift/AppKit 工程（见 mac/README.md）
oracle/mac-contracts/   Windows 上再生 Mac 契约样例的 C# 生成器
tests/                  无需测试框架的自测（When、Markdown、Card、Layout、Store、Fetch、技能）
docs/DESIGN.md          设计说明与取舍记录
docs/MACOS-IMPLEMENTATION.md  macOS 实现记录与实机验收
docs/examples/skills/   技能示例（飞书文档）
```
